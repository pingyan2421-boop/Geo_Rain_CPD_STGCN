# 降雨事件动态蒸馏模型 (Event-Distilled Model)

> 🌧️ **利用降雨事件发生概率与气象风险的端到端混合预测网络**

本目录是专门为您之前设计的**“降雨事件”历史最优模型**单独切出的一份**纯净独立版本 (Clean Environment)**。在这里，所有与事件机制相关的特征工程、Loss 动态加权、以及基于验证集预测误差动态学习门控的方法都被完整保留。

## 🌟 核心特色 (Key Features)

与 `release_source_switch_posthoc_moe`（纯后处理硬切换）不同，本仓库属于**端到端深度学习优化**：

1. **降雨事件特征提取**: 动态追踪 `event_active_3d`, `event_active_7d`, 以及 `antecedent_wetness_index` (前期影响雨量)。
2. **气象风险动态门控**: 根据气象变量 `[probs, wetness]`，系统在验证集上主动学习并生成能够判定高低风险的门控（Gate）权重。
3. **样本级动态蒸馏惩罚**: 
   - 处于降雨高风险（季风雨季且门控 $w \ge 0.5$）的样本，蒸馏损失比重翻倍至 $2.0$。
   - 处于气候平稳期（非降雨季），降低拟合惩罚至 $0.5$。
4. **预测入口智能分流 (Hybrid Routing)**: 针对业务落地创新设计的兜底策略。在低信度或雷达降级区（Fallback）沿用原生基线，在高信度区（Official）自动切换至全量高敏蒸馏模型，实现“保下限、捅上限”的全局最优解。

## 📖 核心术语释义 (Glossary)

为了帮助您更好地理解本架构的运行机制，以下是对模型中独有名词的详细定义：

- **降雨事件 (Rainfall Event)**：打破“仅看当日降水”的局限，将其视为一个动态的物理衰减过程。通过引入活跃窗口（3天/7天/15天）来评估极端降水对地质体形变的持续和滞后影响。
- **前期影响雨量 (Antecedent Wetness Index, AWI / Wetness)**：水文学概念。通过衰减因子（如 $\alpha = 0.8$）计算过去几十天降水的指数累加值，客观表征山体或土壤当前的“饱和度”与“湿润等级”。
- **历史触发概率 (Historical Trigger Probability / Probs)**：基于贝叶斯先验统计提取的气象风险特征。它量化了在历史上相同的“湿度等级”和“降雨等级”下，真实诱发显著位移事件的概率。
- **气象风险动态门控 (Dynamic Gating)**：一个轻量级的可解释机器学习监督器（逻辑回归）。它以 `[probs, wetness]` 为输入，在验证集上主动学习并输出连续的门控权重 $w \in (0,1)$，从而在“常态演化回归专家”与“极端气象鲁棒专家”之间实现智能且平滑的软性切换。
- **样本级动态蒸馏惩罚 (Adaptive Sample Weighting)**：在训练损失（Loss）计算中引入的一种靶向注意力机制。系统会根据样本的“事件高危程度”动态分配惩罚比重（如季风期高危时权重飙升至 2.0，平稳期降至 0.5），强迫模型在长步长预测中死磕降雨特征。
- **雨敏点 (Rain Sensitive Point)**：地表形变监测网络中，对降水渗透极度敏感、在雨季极易发生突发性加速滑动的观测点。
- **多种子交叉验证 (Random Seed / Multi-Seed Validation)**：由于深度学习在参数初始化、随机失活（Dropout）等环节存在天然的随机性，如果只跑一次，极容易将“运气好”当成“模型好”。本架构强制要求在 3 个截然不同的“随机数种子”（如 `0`, `7`, `23`）下独立从头跑完全部管线，并最终汇报平均误差。这从根本上杜绝了偶然性，砸实了学术结论的严谨度。

## 🧠 【教学级解析】我们是如何利用降雨事件与气象因素进行预测的？

在传统的深度学习（如纯 STGCN 或 LSTM）中，气象数据（如降雨量）往往只被当作普通的输入特征（Input Features）简单地丢进网络。但由于强降雨在整个时间序列中是极其稀疏的，神经网络极易将其当作“噪声”忽略，进而造成一旦遭遇汛期就会出现的“长步长（如 H+5）预测退化”。

为了从根本上解决这一问题，本架构将降雨事件与气象因素升格为**“先验知识监督者 (Prior Knowledge Supervisor)”**。以下是这套架构完整的运作逻辑和底层算法详解，供教学与深入研究参考：

### 第一步：前期因子选择与气象风险提取 (Feature Engineering & Selection)

我们并没有把“当日降雨量”直接喂给网络，因为水文地质的响应存在**严重的滞后性与累积效应**。为此，我们精心设计了以下气象风险因子及其计算算法：

1. **前期影响雨量 (Antecedent Wetness Index, AWI / Wetness)**
   - **选择逻辑**：昨天的雨今天还在土里。单日大雨不一定引发滑坡，但如果前期土壤已经吸饱了水，哪怕是一场小雨也可能成为压死骆驼的最后一根稻草。因此我们需要一个指标来衡量山体内部真实的“水分饱和度”。
   - **算法逻辑**：采用水文学中的**指数衰减累加算法**。其核心公式类似于 $AWI_t = P_t + \alpha \times AWI_{t-1}$，其中 $P_t$ 是当天的降雨量，$\alpha$ 是衰减系数（例如设为 0.8，代表每天保留 80% 的水分，其余蒸发或流失）。通过递归计算过去几十天的降水，它能极其精准地描绘出土壤的“湿润等级”。
2. **降雨事件活跃度衰减 (Event Active Constraint)**
   - **选择逻辑**：地表位移对极端天气的响应往往集中在灾害发生后的几天内。
   - **算法逻辑**：系统设定了多尺度的活跃时间窗（如 3天、7天、15天）。算法会回溯距离当前最近的一次极端降水事件，并根据时间差应用衰减函数（距离越近值越高）。如 `event_active_3d` 能够敏锐捕捉近期刚发生的暴雨冲击。
3. **基于贝叶斯的历史触发概率 (Historical Trigger Probability / Probs)**
   - **选择逻辑**：即便知道了当前的土壤湿度和当天的雨量，真正引发位移的概率有多大？这需要向历史数据“请教”。
   - **算法逻辑**：采用**贝叶斯先验统计**。算法将历史数据划分为不同的“湿度等级”与“降雨等级”网格。在每一个网格中，统计历史上真实诱发了“显著位移事件”的频率。以此计算出条件概率 $P(\text{位移} | \text{当前湿度}, \text{当前降水})$，将物理量直接转化为机器能理解的“危险概率值”。

### 第二步：训练气象监督器产生门控 (Meteorological Supervisor & Gating)

有了上述三大极具物理意义的特征组合（以 `[probs, wetness]` 为代表），我们将它们输入到一个**独立且轻量级的机器学习模型**（在这里我们选用了具有极强可解释性的**逻辑回归 Logistic Regression**）。
- **学习逻辑**：在验证集上，我们同时跑两个基线网络：一个是拟合常态极准的“常态演化回归专家”，另一个是抗噪极强的“极端气象鲁棒专家”。逻辑回归监督器会主动学习：在当前的气象风险特征下，哪个专家的误差更小？
- **输出结果**：监督器最终输出一个连续的**动态门控权重 $w \in (0,1)$**。当 $w$ 接近 1，说明当前极其危险，必须听极端气象鲁棒专家的。

### 第三步：生成混合的“软教师” (Generating the Soft Teacher)

基于监督器给出的动态门控权重 $w$，我们将两位专家的预测结果按比例动态混合。这样就生成了一个“复合软教师 (Composite Teacher)”：在天晴时它表现平稳，在暴雨时它警惕性极高。它成为了一个近乎完美的预测基准（标签）。

### 第四步：气象驱动的靶向蒸馏训练 (Risk-Aware Distillation)

在最终的深度图神经网络端到端训练中，气象因素做出了最后也是最重要的一次干预——**控制损失函数（Loss）的惩罚力度**：
- **区别对待**：当门控 $w \ge 0.5$（即系统判定处于降雨高危的季风期），系统会将当前样本的学习惩罚权重猛增至 **$2.0$**。反之在非降雨季，惩罚降至 **$0.5$**。
- **教学意义**：这种“靶向蒸馏”强迫神经网络在训练时不能再对稀疏的降雨事件视而不见，它必须“死死咬住”由高危降雨特征主导的教师预测结果。这就从根本上克服了网络由于“只背均值”而导致的雨季长步长预测滞后与失真。

### 第五步：后续全阶段（全局）综合预测机制与验证 (Global Full-Stage Prediction)

如果仅仅在一个时间切片（例如单纯在 `cp_180` 阶段）上表现优异，深度学习模型很可能是“过拟合”了该特定时期的数据。为了教学与验证的严谨性，证明气象驱动蒸馏机制的长效鲁棒性，本模型设计了**全阶段/多阶段综合预测机制**：

1. **CPD 动态切片与时序阶段化**：
   现实中的地质体形变并非匀速线性，而是呈现出受气象触发的“阶段性突变”（如雨季加速、旱季平稳）。模型后台利用 CPD（变化点检测算法），自动将连续的位移时序切分为多个演化阶段。
2. **聚焦关键阶段，克服“冷启动”**：
   在早期的变化点（如 `cp_35`、`cp_80`），历史数据极其匮乏（数据饥饿），此时强行训练深度图卷积网络（STGCN）会导致模型无法正常收敛（冷启动问题）。因此，我们的全阶段综合预测策略是：**放弃早期无效阶段，聚焦于数据累积最充分、气象环境最恶劣、旱雨季切换最剧烈的“尾部全阶段”（如 `cp_160` 与 `cp_180` 的联合验证）**。
3. **跨阶段全局泛化与检验**：
   在后台的完整运行管线中，系统不仅预测 `cp_180`，还会回滚到 `cp_160` 等前期大阶段。模型需要在不同切分节点上，独立执行“门控生成”、“教师混合”与“蒸馏重训”。只有当模型跨越多个不同气象环境的全阶段（Global 两折综合），依然能在 H+5 这样的长步长上实现误差的全面缩减时，才能在科学上断定：模型真正学到了“降雨触发位移”的物理规律，而非巧合。
